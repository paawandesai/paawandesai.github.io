### What it does
A Qwen3-4B fine-tuned with LoRA (trained on Modal) that turns a plain-language payment spec into a NACHA ACH file. That's the strict 94-character fixed-width format US banks use for ACH payments. One wrong character fails the file. A code validator checks every output for exact correctness, and a Claude Haiku judge scores spec adherence.

### Results (exact-match files)

| Model | Head-to-head (20) |
| --- | --- |
| Claude Opus | 17 |
| **This 4B model, running locally** | **15** |
| GPT-5.5 | 3 |
| Claude Sonnet | 1 |

The tuned model also scores 38/50 on the eval set and 85/100 on the holdout set. The untuned base model scores 0/50 on the eval set. A self-training round is in progress. It doesn't yet generalize to originator names it never saw in training, and that gap is tracked openly.

### How it was built
- **Find a real gap first.** I tested candidate tasks like financial statement spreading and chest X-ray reading and dropped them because frontier models were already good enough. Exact fixed-width banking files were not.
- **Generate data by code, filter with an exact checker.** Every training example is generated by code and kept only if the validator passes it.
- **One command reproduces the results table** comparing the base and tuned models.

### Tools
Python, Qwen3-4B, LoRA, Modal, vLLM, Hugging Face, Claude Haiku as judge
